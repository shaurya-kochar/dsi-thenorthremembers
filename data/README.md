# Data

## Synthetic NGO cases (`synthetic/`)

Seven cases, each with `sources/` (what the pipeline ingests) and `gold.json` (the answer key).

| Case | Sources | Split |
|---|---|---|
| case_01_simple | events sheet, organiser e-mail | build |
| case_02_medium | volunteer roster (Excel), WhatsApp group, first-aid PDF | build |
| case_03_conflict | members, registrations, coach WhatsApp group, programme rules PDF | build |
| case_04_sunday_long_run | signup sheet (Excel), event plan PDF, coordinators' WhatsApp group, WHO heat-and-health excerpt (public slice) | build (demo) |
| case_05_volunteer_attendance | attendance log, volunteers' WhatsApp group, report e-mail | build |
| case_06_event_schedule | Q4 events sheet, newsletter e-mail | held-out |
| case_07_race_day_logistics | aid station plan PDF, station leads' WhatsApp group | held-out |

19 synthetic files, 102 unique entities (people, events, programmes, places) and 27 planted conflicts. Cases 04-07 are generated by `scripts/build_hack1_data.py` (seeded, so re-running gives the same data); the generator writes each planted conflict and every mention into `gold.json` while it writes the text.

Each `gold.json` lists `entities` (every mention as text + chunk id), `conflicts` (both values, how they appear in the text, and the chunks they come from), and `split`. `facts` and `queries` for the new cases are added with the test questions (issue #10).

**Split:** `split.json`. Cases 06 and 07 (8 of the 27 conflicts, about 30%) are held out for final testing and must not be used for tuning.

**Planted conflicts:** different dates, times or counts for the same event; volunteers marked absent in one file and present in another; changed phone numbers and signup statuses; and the same person spelled two ways.

**Privacy:** no real Hyderabad Runners member data. Names come from Faker (en_IN) combined at random, phone numbers are random, and every e-mail address uses the reserved `example.org` domain.

## Public data (`public/`)

Fetched with `scripts/fetch_public_data.py`; sources and licences in `public/manifest.json`.

- `openalex/`: 200 paper records on recreational running, marathon health, community physical activity, heat illness and event volunteering. Author names and affiliations are dropped.
- `who/`: five WHO open-access reports (physical activity guidelines, global action plan, 2022 status report, heat and health, mass gatherings), six text-heavy pages each.
- `ogd/`: two OGD India tables. The data.gov.in API needs a personal key (free); run `DATA_GOV_IN_API_KEY=... python scripts/fetch_public_data.py --ogd --skip-who --skip-openalex`.
